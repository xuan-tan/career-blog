> Authoritative type & layout spec. **Read this before touching `assets/css/` or `layouts/`.**
> Companion to `.sitemap-reference.md` (structure) — this file covers *styling intent*.
>
> Created: 2026-09-20 · Branch: `cc/editorial-type-system`

---

## 0. The one principle

**Hierarchy is carried by scale, weight and ink value — never by decoration.**

No boxes to separate things. No icons to signal importance. No colour-coding to create
structure. If two elements need to be distinguished, they differ in **size**, **weight**, or
**grey**. If they can't be distinguished that way, they don't belong on the page.

Corollary: **when something isn't working, the fix is almost never "add a border."**

## 1. Typefaces — three roles, no overlap

| Role | Family | Why |
|---|---|---|
| **Display** | **EB Garamond** (variable, `wght 400–800`, true italic) | Classical French old-style. Warm, literary, conventional letterforms — suits a documentary travel/craft journal. Full weight range, so weight remains a lever. |
| **Text** | **Newsreader** (variable, `opsz 6–72`, `wght 200–800`, true italic) | Purpose-built for long-form reading. Optical axis keeps body copy crisp at 18px and elegant in pull quotes at 30px. Quiet where Fraunces is loud. |
| **Meta / UI** | **Inter** (variable) | Neutral grotesque. Its only job is to be *not-serif* so labels, dates and tags read as system chrome rather than content. |
| **Code** | `ui-monospace` stack | Unchanged. |

**Display face history.** Fraunces was the first pick and was **dropped**: it draws an intrinsic
descending squiggle on the capital J. Verified by pixel diff that the J glyph is *identical*
across `WONK 0` and `WONK 1`, and that no stylistic alternate (`ss01`–`ss03`, `salt`,
`cv01`–`cv03`) changes it — the quirk cannot be tuned away, only swapped away.

EB Garamond replaced it. It has **no optical-size axis**, so display and text no longer differ
by optical size — the contrast between them is one of *typographic colour* instead: Garamond is
airy and high-contrast with small x-height, Newsreader is sturdier and more robust. That reads
correctly (like a book's title page vs its body), but it is a **quieter, less punchy contrast**
than a Didone would give. If the headlines ever feel underpowered, the escalation path is
**Bodoni Moda** or **Playfair Display** — one line in `extend-head.html` plus the
`--font-display` token.

**Why three families and not one:** an editorial hierarchy needs a *contrast axis*. Serif vs
sans does that work instantly and cheaply. Two serifs (Garamond + Newsreader) split the job of
"loud" and "quiet" so neither has to compromise.

## 2. Type scale

Fluid, `clamp()`-based. No fixed px anywhere in the type system. Ratio ≈ **1.25** in the text
range, ≈ **1.333** in the display range (bigger steps where the eye needs them).

### Display (Fraunces)
| Token | Size | Use |
|---|---|---|
| `--type-hero` | `clamp(2.5rem, 1.6rem + 4.2vw, 4.75rem)` | Full-bleed hero title (`{{< hero >}}`) |
| `--type-display-xl` | `clamp(2.75rem, 1.5rem + 5.5vw, 5.5rem)` | Landing hero only |
| `--type-display-l` | `clamp(2.25rem, 1.4rem + 3.6vw, 3.75rem)` | Feature post headline, section hero |
| `--type-display-m` | `clamp(1.75rem, 1.2rem + 2.2vw, 2.625rem)` | List page title, feature card title |

### Headings (Fraunces)
| Token | Size | Use |
|---|---|---|
| `--type-h1` | `clamp(2rem, 1.3rem + 3vw, 3.25rem)` | Article title |
| `--type-h2` | `clamp(1.5rem, 1.15rem + 1.5vw, 2.125rem)` | Article section head |
| `--type-h3` | `clamp(1.25rem, 1.1rem + 0.7vw, 1.5rem)` | Sub-section |
| `--type-h4` | `1.125rem` | Rare; run-in head |

### Text (Newsreader)
| Token | Size | Use |
|---|---|---|
| `--type-lead` | `clamp(1.25rem, 1.1rem + 0.7vw, 1.625rem)` | Article standfirst / section intro |
| `--type-body` | `clamp(1.0625rem, 1rem + 0.3vw, 1.1875rem)` | Body copy (17→19px) |
| `--type-small` | `0.9375rem` | Fine print, footnotes, table body |
| `--type-caption` | `0.8125rem` | Figcaptions, image credits |

### Meta (Inter)
| Token | Size | Use |
|---|---|---|
| `--type-meta` | `0.75rem` | Eyebrows, dates, tags, card kickers |
| `--type-micro` | `0.6875rem` | Badges only |

## 3. Ink ramp

Warm greys, tuned for **dark-first** rendering (`defaultAppearance = "dark"`).
Pure `#fff` and pure `#000` are **never** used for text or surface.

### Dark (primary)
| Token | Value | Use |
|---|---|---|
| `--surface-0` | `#1B1A18` | Page background (warm near-black) |
| `--surface-1` | `#242220` | Raised: cards, code blocks |
| `--ink-0` | `#F2EFE9` | Display + headings. *Never body copy.* |
| `--ink-1` | `#D6D1C8` | Body copy |
| `--ink-2` | `#A39D93` | Captions, secondary text |
| `--ink-3` | `#7A756C` | Meta, eyebrows, disabled |
| `--ink-4` | `#3A3733` | Rules, dividers, borders |
| `--accent` | `#D4915A` | Links, active states, hover underline |

### Light (mirror)
`--surface-0 #FBF9F6` · `--surface-1 #F2EEE8` · `--ink-0 #1B1A18` · `--ink-1 #35322E` ·
`--ink-2 #6B655C` · `--ink-3 #8F887D` · `--ink-4 #DCD6CC` · `--accent #A9601F`

### The grey rules
1. **Headings use `--ink-0`, body uses `--ink-1`.** The step down is deliberate — it stops body
   copy competing with headlines. Old site had both near-white; that's the flatness.
2. **Never go below `--ink-1` for anything you expect to be read.** `--ink-2` is for supporting
   material (captions, credits). `--ink-3` is for labels, not prose.
3. **Rules are `--ink-4` and hairline (1px).** A rule should be *felt*, not seen.
4. **One accent only.** `--accent` marks links and active nav. It never colours text that
   isn't interactive, and never fills a block.

## 4. Weight

| Weight | Role |
|---|---|
| **600** | Display XL/L. Headlines at hero scale only. |
| **500** | H2–H4, card titles, meta labels. The workhorse heading weight. |
| **400** | All body copy. Pull quotes. |
| **300** | Oversized display pull quotes only (Fraunces at display size). |

**Rules**
- Display sizes use **negative tracking** (`-0.02em`); body uses `0`; meta uses `+0.12em`.
- Never set heading weight above 600. Bold-heavy headings kill the editorial register and read
  as "corporate deck".
- Body copy is **always 400**. Weight changes inside prose are a hierarchy failure.

## 5. Bold vs Italic — the discipline

These are two different tools and they've been conflated.

### Italic = *voice*
Use italic when the words are not the author's, or are being invoked rather than stated:
- Pull quotes
- Titles of works (*Scenes from the Alps*, books, films)
- Foreign words (*passo*, *dolce far niente*)
- Editorial asides and hedged parentheticals
- Captions' attribution

### Bold = *structure*
Use bold when the reader needs an anchor to scan to:
- Defined terms on first use
- Key figures in data-heavy passages
- Table headlines and stat callouts
- The lead-in phrase of a standfirst

### Nothing = decoration
**Never bold or italicise for emphasis mid-sentence.** If a sentence needs a word shouted,
rewrite the sentence. If a paragraph needs a signpost, it needs a subhead — not bold text.

**Never combine.** No bold-italic outside of pull quotes.

## 6. Leading & measure

| Context | Line-height | Measure |
|---|---|---|
| Display | `1.05` | n/a (max 20ch) |
| H2/H3 | `1.15` | n/a |
| Body | `1.6` | `68ch` |
| Lead / standfirst | `1.45` | `50ch` |
| Caption | `1.45` | `46ch` |
| Meta | `1.2` | n/a |

Headings get **top-heavy spacing**: `margin-top: 2.5em`, `margin-bottom: 0.5em` (in em, so it
scales). Whitespace above a heading belongs to that heading.

Paragraph rhythm: `margin-bottom: 1.35em`, no first-line indent, no extra space after headings
that follow body copy mid-flow.

## 7. Layout — the editorial grid

Replace Blowfish's uniform 3-up card grid with a **feature-led asymmetric grid**.

### List page (blog/travel)
1. **Eyebrow** — section label, Inter uppercase, `--ink-3`
2. **Display title** — `--type-display-l`, `--ink-0`
3. **Standfirst** — `--type-lead`, `--ink-2`, max 50ch
4. **Feature card** — newest/featured post, full content-width. Image 5:2 on desktop, title
   `--type-display-m`, standfirst. No box, no border. Title and standfirst share a **first
   baseline** (`align-items: baseline`), not a box top.
5. **Asymmetric grid** — 12-col: first two entries at 6 cols each (2-up), remaining at 4 cols
   (3-up). Collapses to 1-col under 640px, 2-col under 1000px.
6. **Divider** between feature and grid: hairline, `--ink-4`, full width.

**Hierarchy rule:** the page `h1` is never smaller than any entry title on that page.
Levels descend `display-l` (page title) → `display-m` (feature) → `h2` (2-up card titles) →
`h3` (4-up card titles). A text-only feature (`.ed-feature--note`) steps *up* to `display-l`,
because it has no banner image to carry it.

### Card treatment
- **No borders, no rounded corners, no card background.** Separation by whitespace only — the
  single deliberate exception is the metadata bar.
- Structure, top to bottom: **image → title → standfirst/summary → metadata bar.**
  **Nothing sits above the title.**
- Hover: image scales `1.02`, title underline in `--accent`. That's the whole interaction.
- Exception: if a card genuinely needs a surface (e.g. over an image), use `--surface-1`.

#### Why nothing sits above the title
An earlier version kept the descriptor ("7 entries") as a kicker above the title. But only
*some* cards have one — a section with no entries has no count — so those titles sat ~21px
lower than their neighbours in the same row (measured: Italy 1596 vs Japan 1617). Moving all
metadata into one bar at the foot made every card structurally identical and the titles aligned
(Italy/Japan both 1556; NZ/Thailand/Vietnam all 2024). Keep it that way.

#### Every entry gets a thumbnail
The image resolver (`layouts/partials/editorial/image.html`) falls back to Blowfish's
placeholder — `site.Params.defaultFeaturedImage`, currently `assets/img/featured.svg`, an
**animated SVG**, served as-is so it keeps animating. Order: frontmatter `featureimage` →
page-bundle `*feature*`/`*cover*`/`*thumbnail*` → `defaultFeaturedImage`.

Setting `hideFeatureImage: true` on a page opts out of the entire lookup, which falls through
to a **text-only note card** (`.ed-card--note` / `.ed-feature--note`: hairline rule where the
image would be, tighter title). That path still exists and is deliberate — it is just no longer
the default for image-less pages.

**Trade-off to be aware of:** because the placeholder is used, every image-less entry shows the
*same* graphic. That is Xuan's explicit preference (a complete-looking grid beats a
text-only card). The note-card path is what you get when you want the opposite.

#### The metadata bar has TWO ranks — keep them distinct
Both tags and the descriptor live in one bar at the foot of the card
(`.ed-card__tags` / `.ed-feature__tags`): a flex row, **sandwiched between two 1px `--ink-4`
hairlines**, full card width. Built from discrete elements, never a joined string, so tags can be
real links.

| Element | Size | Weight | Ink | Role |
|---|---|---|---|---|
| `.ed-meta__tag` | `--type-micro` (11px) | 400 | `--ink-3` | Navigable. Links to `/tags/<term>/`. Least important, so smallest. |
| `.ed-meta__info` | `--type-meta` (12px) | 500 | `--ink-2` | Descriptor: date, reading time, entry count. Not a link. |
| `.ed-meta__sep` | `--type-micro` | 400 | `--ink-4` | Middle dot. Faintest element on the page. |

They differ by **size AND weight AND ink**, so the ranks stay distinguishable even inside the
same bar. A section with no entries correctly shows a bar containing only its tag, rather than a
misleading "0 entries".

**Gotcha:** the feature's bar needs `grid-column: 1 / -1` via `.ed-feature__tags`, so it runs
under both the title and standfirst columns. If you rename that class the selector silently stops
matching and the bar gets squeezed into a single 56px grid column and wraps.

### Article (Composition mode)
Keeps the existing shortcode blocks (`hero`, `content-block`, `image-block`, `grid`,
`pullquote`, `section-divider`) but they inherit the token system. Prose measure 68ch,
image blocks break out to full width, pull quotes break out slightly wider than prose.

**Hero API:** prefer `title` + `subtitle` params, which emit a real `<h1>` and `<p>`:
```
{{< hero src="featured.jpg" title="Three Passes, Three Days" subtitle="One ridge at a time." height="75" >}}
```
The legacy `overlay="**Title** <br>Subtitle"` form still renders correctly (CSS styles its
leading `<strong>` as display type) but produces no `<h1>`, so **do not use it for new pieces**.

**Centring:** `side="center"` is for standfirsts and ≤2-line passages only. Long-form body
copy is always left-aligned — centred prose has no consistent left edge for the eye to return
to. Centred blocks automatically get a 54ch measure and increased leading.

## 8. Implementation map

| File | Owns |
|---|---|
| `assets/css/type-system.css` | Tokens (`:root`), element mapping, prose rules, editorial list components. **All new work goes here.** Loaded via `layouts/partials/extend-head.html` (the theme ignores `params [custom] css`). |
| `assets/css/custom.css` | Shortcode/editorial block styling + site-specific overrides. Legacy `!important` font rules removed. |
| `assets/css/critical.css` | Untouched — and currently **dead** (not referenced by any template). |
| `layouts/partials/extend-head.html` | Font loading + `type-system.css` resource link. |
| `layouts/_default/editorial-list.html` | Editorial list layout (activated via `layout: editorial-list`). |
| `layouts/partials/editorial/card.html` | Editorial card partial. |

### Rules
- **Tokens are the only place raw values live.** No hex codes or px sizes in component CSS.
- Use `var(--token)` for anything a designer might want to tune. If you're writing a hex code
  in a component, you're doing it wrong.
- `!important` is banned except to override Blowfish's Tailwind utility classes on
  `<body>` / `.prose`, where it's unavoidable.
- New component = new class prefixed `ed-` (editorial).

## 9. Verification — who checks what

```bash
hugo serve --bind 0.0.0.0 --baseURL http://tans-mac-mini.lan:1313 --disableFastRender
```

### The rule
**Xuan is the arbiter of visual truth. Do not screenshot and do not run a vision model.**
Make the change from his description, then he looks at the livereload preview and says whether
it's right. Screenshots + vision-model diagnosis are banned: the agent cannot see an image
anyway, so it ends up trusting a model that has been demonstrably wrong on this project
(claimed `WONK 0` fixed the Fraunces J — it did nothing; called the same nav chevron "too high"
then "too low" on identical renders). Both cost real round trips.

### What the agent SHOULD verify instead — algorithmically
Anything with a numeric answer, checked headlessly with no image in the loop:

- **Computed styles.** `getComputedStyle` for font-size/weight/family/letter-spacing/
  text-transform/colour/grid-column. This is how the meta hierarchy was proven (tag 11px/400/
  `--ink-3` vs descriptor 12px/500/`--ink-2`) and how the feature meta bug was caught
  (`grid-column` collapsing to one 56px column).
- **Geometry.** `getBoundingClientRect` deltas. E.g. chevron centre vs text centre = 0.00px.
- **Link/URL integrity.** Status codes, canonical/`meta refresh` targets, sitemap contents.
- **Breakpoint sweeps.** Loop page × width, assert no horizontal scroll (`scrollX` stays `0`).
  This is what caught the `100vw` overflow across 15 combinations — a real bug no human would
  find exhaustively by eye.
- **Build output.** Rendered HTML, template errors, warnings.

Method: write a throwaway page under `static/` that iframes the page under test (same origin),
reads the numbers, and dumps them into the DOM for `--dump-dom` to pick up. **Delete the
scratch page when done.** Never leave one in `static/`.

### Pitfall: don't trust a screenshot's implied viewport
If you ever do capture something for your own reasoning, size the window to a *true* viewport
(e.g. 1440x900). The homepage hero is sized in `vh` (`height: 100vh`, `font-size: 12.5vh`), so a
tall window such as `--window-size=1440,1800` makes `100vh` = 1800px and renders a distorted
hero that *looks* broken but isn't. (Prefer not to capture at all — see the rule above.)
