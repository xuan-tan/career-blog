---

## 0. The one principle

**Hierarchy is carried by scale, weight and ink value — never by decoration.**

No boxes to separate things. No icons to signal importance. No colour-coding to create
structure. If two elements need to be distinguished, they differ in **size**, **weight**, or
**grey**. If they can't be distinguished that way, they don't belong on the page.

Corollary: **when something isn't working, the fix is almost never "add a border."**

---

## 0.1 How the editorial skin is wired

Three mechanisms, no more. Knowing which one is doing the work is the difference between a
five-minute tweak and an afternoon.

**1. `layout:` picks the template.** A section index opts into the editorial list by declaring
`layout: editorial-list` in its `_index.md`; Hugo then renders `layouts/_default/editorial-list.html`
instead of the theme's section template. That is the *only* switch. It is a front-matter param,
**not a tag** — nothing in `tags:` changes how a page looks.

**2. `type-system.css` restyles what the theme still renders.** Article pages have no editorial
template. They are Blowfish's `single.html`, untouched, and the skin is applied entirely in CSS.
The file loads last (`layouts/partials/extend-head.html`) and is **unlayered**, while the theme's
Tailwind utilities live in `@layer` — so an unlayered rule beats every utility on the page with
no `!important`. That is why `text-xl` and `text-neutral-500` on the `lead` shortcode are dead.

**3. Tokens carry the decisions.** Anything a designer would want to tune is a `var(--token)` in
`:root`; components read tokens and nothing else.

Consequence: **"keeping Hugo's logic under the hood" is exactly right.** Taxonomy pages, TOC,
breadcrumbs, related posts, pagination and the markdown pipeline are all the theme's. We own
type, measure, colour and composition — not structure. Where structure *does* change, it is a
`layouts/` override, never an edit inside `themes/blowfish/`.

`assets/css/custom.css` is **not** the skin. It is bundled into the theme's `main.bundle` and
therefore loads *before* type-system; it holds legacy component styles only. New work goes in
type-system.

**Styling is global and lives above `content/`.** A rule written here applies to every page of that
type — all posts, all list pages — and that is the intent. **No per-page or per-post styling**
unless Xuan asks for it by name; a page that must differ changes composition (`layout:`), not skin.
If a selector needs a page name in it, the change is wrong.

## 0.2 The short version — reread before any change

1. **One skin.** Everything visual lives in `assets/css/type-system.css`. It loads last and is
   unlayered, so it beats every Tailwind utility. Nothing here needs `!important`.
2. **Structure belongs to the theme.** Posts render Blowfish's `single.html`; section indexes
   render `editorial-list.html` because their `_index.md` says `layout: editorial-list`. That
   param is the only switch — **never a tag**.
3. **Tokens hold the numbers.** Size, colour, leading and measure are `var(--…)` in `:root`.
   A raw px or hex inside a component is a bug.
4. **Composition ≠ look.** Which blocks exist and in what order is a `layouts/` template. How
   they look is CSS. Vary composition with `layout:`; never restyle a single page.
5. **Global by default.** A rule lands on every page of that type. No page names or slugs in
   selectors.
6. **Finding a page's layout:** front matter `layout:` → else `_default/single.html` → theme.
   Confirm in the built HTML by fingerprint: `id="single_header"` (Blowfish single),
   `class="editorial-layout"` (`layout: editorial`), `class="ed-list"` (`layout: editorial-list`).

`custom.css` is legacy and loads **before** type-system, so edits there lose. `critical.css` is
dead and loaded nowhere.

Where things go: content and per-page switches → front matter · look → `type-system.css` ·
blocks and order → `layouts/` · behaviour → `assets/js/`.

## 1. Typefaces — three roles, no overlap

| Role | Family | Why |
|---|---|---|
| **Display** | **EB Garamond** (variable, `wght 400–800`, true italic) | Classical French old-style. Warm, literary, conventional letterforms — suits a documentary travel/craft journal. Full weight range, so weight remains a lever. |
| **Text** | **Newsreader** (variable, `opsz 6–72`, `wght 200–800`, true italic) | Purpose-built for long-form reading. Optical axis keeps body copy crisp at 18px and elegant in pull quotes at 30px. Quiet where Garamond is airy. |
| **Meta / UI** | **Inter** (variable) | Neutral grotesque. Its only job is to be *not-serif* so labels, dates and tags read as system chrome rather than content. |
| **Code** | `ui-monospace` stack | Unchanged. |

**Display face history.** Fraunces was the first pick and was **dropped**: it draws an intrinsic
descending squiggle on the capital J. Verified by pixel diff that the J glyph is *identical*
across `WONK 0` and `WONK 1`, and that no stylistic alternate (`ss01`–`ss03`, `salt`,
`cv01`–`cv03`) changes it — the quirk cannot be tuned away, only swapped away.

EB Garamond replaced it. It has **no optical-size axis**, so display and text no longer differ
by optical size — the contrast between them is one of *typographic colour* instead: Garamond is
airy and high-contrast with small x-height, Newsreader is sturdier and more robust. That reads
correctly (like a book's title page vs its body), but it is a **quieter, less punchy contrast**
than a Didone would give. If the headlines ever feel underpowered, the escalation path is
**Bodoni Moda** or **Playfair Display** — one line in `extend-head.html` plus the
`--font-display` token.

**Why three families and not one:** an editorial hierarchy needs a *contrast axis*. Serif vs
sans does that work instantly and cheaply. Two serifs (Garamond + Newsreader) split the job of
"loud" and "quiet" so neither has to compromise.

## 2. Type scale

Fluid, `clamp()`-based. No fixed px anywhere in the type system. Ratio ≈ **1.25** in the text
range, ≈ **1.333** in the display range (bigger steps where the eye needs them).

### Display (EB Garamond)
| Token | Size | Use |
|---|---|---|
| `--type-hero` | `clamp(2.25rem, 1.44rem + 3.78vw, 4.275rem)` | Full-bleed hero title (`{{< hero >}}`) |
| `--type-display-xl` | `clamp(2.475rem, 1.35rem + 4.95vw, 4.95rem)` | Landing hero only |
| `--type-display-l` | `clamp(2.025rem, 1.26rem + 3.24vw, 3.375rem)` | Feature post headline, section hero |
| `--type-display-m` | `clamp(1.575rem, 1.08rem + 1.98vw, 2.3625rem)` | List page title, feature card title |

### Headings (EB Garamond)
| Token | Size | Use |
|---|---|---|
| `--type-h1` | `clamp(1.8rem, 1.17rem + 2.7vw, 2.925rem)` | Article title |
| `--type-h2` | `clamp(1.35rem, 1.035rem + 1.35vw, 1.9125rem)` | Article section head |
| `--type-h3` | `clamp(1.125rem, 0.99rem + 0.63vw, 1.35rem)` | Sub-section |
| `--type-h4` | `1.0625rem` | Rare; run-in head |

### Text (Newsreader)
| Token | Size | Use |
|---|---|---|
| `--type-deck` | `clamp(1.0625rem, 1rem + 0.3vw, 1.1875rem)` | Article's opening paragraph (italic) |
| `--type-lead` | `clamp(1.25rem, 1.1rem + 0.7vw, 1.625rem)` | Article standfirst / section intro |
| `--type-body` | `clamp(1rem, 0.95rem + 0.15vw, 1.0625rem)` | Body copy (16→17px) |
| `--type-small` | `0.9375rem` | Fine print, footnotes, table body |
| `--type-caption` | `0.8125rem` | Figcaptions, image credits |

### Meta (Inter)
| Token | Size | Use |
|---|---|---|
| `--type-meta` | `0.75rem` | Eyebrows, dates, tags, card kickers |
| `--type-micro` | `0.6875rem` | Badges only |

## 3. Ink ramp

Warm greys, tuned for **dark-first** rendering (`defaultAppearance = "dark"`).
Pure `#fff` and pure `#000` are **never** used for text or surface.

### Dark (primary)
| Token | Value | Use |
|---|---|---|
| `--surface-0` | `#1B1A18` | Page background (warm near-black) |
| `--surface-1` | `#242220` | Raised: cards, code blocks |
| `--ink-0` | `#F2EFE9` | Display + headings. *Never body copy.* |
| `--ink-1` | `#D6D1C8` | Body copy |
| `--ink-2` | `#A39D93` | Captions, secondary text |
| `--ink-3` | `#7A756C` | Meta, eyebrows, disabled |
| `--ink-4` | `#3A3733` | Rules, dividers, borders |
| `--accent` | `#D4915A` | Hover states, active nav |
| `--route-ink` | `#B5532E` | Prose links, and the drawn ride line on map shortcodes |

### Light (mirror)
`--surface-0 #FBF9F6` · `--surface-1 #F2EEE8` · `--ink-0 #1B1A18` · `--ink-1 #35322E` ·
`--ink-2 #6B655C` · `--ink-3 #8F887D` · `--ink-4 #DCD6CC` · `--accent #A9601F`

### The grey rules
1. **Headings use `--ink-0`, body uses `--ink-1`.** The step down is deliberate — it stops body
   copy competing with headlines. Old site had both near-white; that's the flatness.
2. **Never go below `--ink-1` for anything you expect to be read.** `--ink-2` is for supporting
   material (captions, credits). `--ink-3` is for labels, not prose.
3. **Rules are `--ink-4` and hairline (1px).** A rule should be *felt*, not seen.
4. **One accent only.** `--accent` marks links and active nav. It never colours text that
   isn't interactive, and never fills a block.

## 4. Weight

| Token | Value | Role |
|---|---|---|
| `--weight-display` | **500** | H1 and display type. |
| `--weight-heading` | **500** | H2–H4, card titles, meta labels. The workhorse. |
| `--weight-body` | **400** | All body copy. Pull quotes. |
| `--weight-light` | **300** | Reserved — oversized display pull quotes only. |

One weight above body, not a ladder. Measured on 2026-10-25: `h1` 46.8px/500, `h2` 30.6px/500, body 17px/400 — the
hierarchy is carried by size and ink, and adding weight on top of that reads as a corporate deck.

**Rules**
- Display sizes use **negative tracking** (`-0.02em`); body uses `0`; meta uses `+0.12em`.
- Never set a heading above 500. If a heading feels weak, it is too small — not too light.
- Body copy is **always 400**. Weight changes inside prose are a hierarchy failure.

## 5. Bold vs Italic — the discipline

These are two different tools and they've been conflated.

### Italic = *voice*
Use italic when the words are not the author's, or are being invoked rather than stated:
- Pull quotes
- Titles of works (*Scenes from the Alps*, books, films)
- Foreign words (*passo*, *dolce far niente*)
- Editorial asides and hedged parentheticals
- Captions' attribution

### Bold = *structure*
Use bold when the reader needs an anchor to scan to:
- Defined terms on first use
- Key figures in data-heavy passages
- Table headlines and stat callouts
- The lead-in phrase of a standfirst

### Nothing = decoration
**Never bold or italicise for emphasis mid-sentence.** If a sentence needs a word shouted,
rewrite the sentence. If a paragraph needs a signpost, it needs a subhead — not bold text.

**Never combine.** No bold-italic outside of pull quotes.

## 6. Leading & measure

| Context | Line-height | Measure |
|---|---|---|
| Display | `1.05` | n/a (max 20ch) |
| H2/H3 | `1.15` | n/a |
| Body | `1.6` | `68ch` |
| Lead / standfirst | `1.45` | `50ch` |
| Caption | `1.45` | `46ch` |
| Meta | `1.2` | n/a |

Headings get **top-heavy spacing**: `margin-top: 1.25em` (`--space-heading-top`), `margin-bottom:
0.5em` (in em, so it scales). Whitespace above a heading belongs to that heading. Halved from
2.5em on 28 Oct 2026 — 76px of air over an h2 read as a gap rather than a break, and the
paragraph's own 1.35em bottom margin is smaller, so it collapses under the heading's.

Paragraph rhythm: `margin-bottom: 1.35em`, no first-line indent, no extra space after headings
that follow body copy mid-flow.

## 7. Layout — the editorial grid

Replace Blowfish's uniform 3-up card grid with a **feature-led asymmetric grid**.

### List page (blog/travel)
1. **Eyebrow** — section label, Inter uppercase, `--ink-3`. Resolution order in
   `editorial-list.html`: explicit `kicker:` in the section's `_index.md` → else the **parent
   section's title** (`craft/bikes` → "Craft", `journal/travel/japan` → "Travel") → else nothing.
   It used to default to the literal string "Journal", so every section without a `kicker` claimed
   to be Journal — including Bikes, under Craft. Top-level sections have no ancestor to name, so
   they render no eyebrow.
2. **Display title** — `--type-display-l`, `--ink-0`
3. **Standfirst** — `--type-lead`, `--ink-2`, max 50ch
4. **Feature card** — newest/featured post, full content-width. Image 5:2 on desktop, title
   `--type-display-m`, standfirst. No box, no border. Title and standfirst share a **first
   baseline** (`align-items: baseline`), not a box top.
5. **Asymmetric grid** — 12-col: first two entries at 6 cols each (2-up), remaining at 4 cols
   (3-up). Collapses to 1-col under 640px, 2-col under 1000px.
6. **Divider** between feature and grid: hairline, `--ink-4`, full width.

**Hierarchy rule:** the page `h1` is never smaller than any entry title on that page.
Levels descend `display-l` (page title) → `display-m` (feature) → `h2` (2-up card titles) →
`h3` (4-up card titles). A text-only feature (`.ed-feature--note`) steps *up* to `display-l`,
because it has no banner image to carry it.

### Card treatment
- **No borders, no rounded corners, no card background.** Separation by whitespace only — the
  single deliberate exception is the metadata bar.
- Structure, top to bottom: **image → title → date · reading time → summary → metadata bar.**
  **Nothing sits above the title.**
- Hover: image scales `1.02`, title underline in `--accent`. That's the whole interaction.
- Exception: if a card genuinely needs a surface (e.g. over an image), use `--surface-1`.

#### The post line: date then reading time, under the title
A post card reads **title / `3 Sep 2026 · 1 min read` / summary / bar**. The date and reading
time sit together on their own line directly under the title, so the piece's own facts are
grouped and the summary reads as the description beneath them.

`.ed-card__postmeta` / `.ed-feature__postmeta`, styled `--type-micro` / Inter / 400 / `--ink-3`.

- **Sections get no post line** — they have no date or reading time (their entry count stays in
  the bar), so the line simply does not render for them.
- A post with no `date` in frontmatter shows the reading time alone.
- The feature keeps its **title | standfirst two-column split**, so its post line sits inside the
  title column: `.ed-feature__heading` is a `display: block` wrapper carrying
  `grid-column: 1 / span 6`.

Do not move the date or reading time into the metadata bar: the bar is for the filterable
things (tags), not for facts about the piece itself.

#### Why nothing sits above the title
An earlier version kept the descriptor ("7 entries") as a kicker above the title. But only
*some* cards have one — a section with no entries has no count — so those titles sat ~21px
lower than their neighbours in the same row (measured: Italy 1596 vs Japan 1617). Moving all
metadata into one bar at the foot made every card structurally identical and the titles aligned
(Italy/Japan both 1556; NZ/Thailand/Vietnam all 2024). Keep it that way.

#### Every entry gets a thumbnail
The image resolver (`layouts/partials/editorial/image.html`) falls back to Blowfish's
placeholder — `site.Params.defaultFeaturedImage`, currently `assets/img/featured.svg`, an
**animated SVG**, served as-is so it keeps animating. Order: frontmatter `featureimage` →
page-bundle `*feature*`/`*cover*`/`*thumbnail*` → `defaultFeaturedImage`.

Setting `hideFeatureImage: true` on a page opts out of the entire lookup, which falls through
to a **text-only note card** (`.ed-card--note` / `.ed-feature--note`: hairline rule where the
image would be, tighter title). That path still exists and is deliberate — it is just no longer
the default for image-less pages.

**Trade-off to be aware of:** because the placeholder is used, every image-less entry shows the
*same* graphic. That is Xuan's explicit preference (a complete-looking grid beats a
text-only card). The note-card path is what you get when you want the opposite.

#### The metadata bar has TWO ranks — keep them distinct
Both tags and the descriptor live in one bar at the foot of the card
(`.ed-card__tags` / `.ed-feature__tags`): a flex row, **sandwiched between two 1px `--ink-4`
hairlines**, full card width. Built from discrete elements, never a joined string, so tags can be
real links.

| Element | Size | Weight | Ink | Role |
|---|---|---|---|---|
| `.ed-meta__tag` | `--type-micro` (11px) | 400 | `--ink-3` | Navigable. Links to `/tags/<term>/`. Least important, so smallest. |
| `.ed-meta__info` | `--type-meta` (12px) | 500 | `--ink-2` | Descriptor: entry count, for a section. Not a link. (A post's date/reading time is NOT here — see "The post line".) |
| `.ed-meta__sep` | `--type-micro` | 400 | `--ink-4` | Middle dot. Faintest element on the page. |

They differ by **size AND weight AND ink**, so the ranks stay distinguishable even inside the
same bar. A section with no entries correctly shows a bar containing only its tag, rather than a
misleading "0 entries".

**Gotcha:** the feature's bar needs `grid-column: 1 / -1` via `.ed-feature__tags`, so it runs
under both the title and standfirst columns. If you rename that class the selector silently stops
matching and the bar gets squeezed into a single 56px grid column and wraps.

### Article (Composition mode)
Keeps the existing shortcode blocks (`hero`, `content-block`, `image-block`, `grid`,
`pullquote`, `section-divider`) but they inherit the token system. Prose measure 68ch,
image blocks break out to full width, pull quotes break out slightly wider than prose.

#### The article row — text + TOC, centred
Article pages are the theme's `single.html`. Its row is `.prose`-capped at 65ch, so the cap lands
on the *pair* (text + TOC) rather than on the text: measured at 1512px the row was 712px, split
into 452px of text and 260px of TOC, with 312px of dead space to its right and body copy at ~50
characters. Fixed in type-system §F:

- the row is `--article-row` (**61rem** = 68ch text + 16rem TOC + 2.5rem gutter) and
  `margin-inline: auto`;
- the text column takes the measure, `max-width: calc(var(--article-row) - 18.5rem)`;
- `lg:ms-auto` on the TOC wrapper is cancelled, because it pinned the TOC to the far right;
- the header takes the same width, so its left edge is flush with the text column;
- a page with no TOC (`:not(:has(.toc))`) drops the empty column so the text still centres.

Measured after: row 944px at 284/1228 on a 1512px viewport — 284px of margin on both sides,
text 644px (67.8ch), TOC 228px. `--article-row` is sized to 68ch of `--type-body` (645px at 17px)
plus the 18.5rem TOC column, so it follows the body size.

#### Links
Prose links are `--route-ink` and carry **no underline** — the same ink the drawn route uses on the
map shortcodes. `layouts/shortcodes/route-step.html` reads the token at map load, with the hex kept
only as a fallback if the variable is ever missing, so line and links cannot drift. The global
`a { color: inherit }` meant an article link was identical to body copy until hover, so colour is
the only thing that makes it a link; an underline under every one was decoration, not signal
(28 Oct 2026). Hover and keyboard focus go to `--accent`. Under `forced-colors: active` the colour
is remapped away, so the underline comes back.

Caveat, measured both ways because the modes differ: link ink is **4.71:1 on `--surface-0` in
light mode but 3.51:1 in the dark default** (body text wants 4.5:1), and against body ink it is
2.58:1 light / 3.26:1 dark, so the colour-only differentiator misses the 3:1 rule in light mode and
the text-contrast floor in dark. `--route-ink` is also not mirrored in the `html:not(.dark)` block,
so light mode inherits the dark value. Accepted deliberately; ~`#9C4425`, or a light-mode token,
clears it if that ever changes.

#### Tables
Banded, not ruled. `tbody tr:nth-child(even)` takes `--surface-1` — one step off the page — and
the per-cell `border-bottom` is removed, so the header rule is the only line. A 30-row geometry
table is read row-wise; hairlines alone lose the eye, and banding plus hairlines is noise.

Cell padding is `--space-cell-y` / `--space-cell-x` (0.8em / 0.45em), with 0.5rem on the outer
cells. Horizontal is deliberately tight: at 0.7em the six-column geometry table started wrapping
and rows grew 44 → 76px. Measured after: 50px rows, no overflow.

#### The deck
The opening paragraph — before the first H2 — reads as a standfirst, and it is **italic**, because
§5 says italic is voice: this line is addressed to the reader, not part of the argument.

- `--type-deck` (**19px** at desktop) — three steps below the h2 (30.6) and two above body (17).
  At lead size (26) it sat too close to the heading it introduces and read as a second h2.
- `--leading-lead` 1.45, `--ink-2`, 50ch measure (580px, narrower than the 644px body column, so
  it is visibly a different register).
- A 1px `--ink-4` hairline closes the block, spanning the deck's own 523px measure rather than
  the 644px column — it ends the preamble instead of ruling the page. 18px below the text.
- With the rule doing the separating, `p:first-child + h2` drops to `margin-top: 2rem` (32px),
  so the pair reads as one unit rather than two spaced paragraphs.

Selector is `.article-content > p:first-child`, so it only fires when the post genuinely opens
with a paragraph. A post that opens with a hero or the `lead` shortcode is untouched — that is
the guard, not a class.

#### Related cards
The theme renders these as bordered tiles with a fixed 150px thumbnail and the article's `h2`
sizing inside a ~200px column. Measured: **204×594**, nearly 1:3, with a 30.6px title, a 17px
summary and tag badges wrapping onto three rows.

Brought onto the card scale in §F:
- thumbnail `aspect-ratio: 1/1` (square, centre-cropped by `object-cover`) instead of the theme's
  fixed `height: 150px` — 4:3 in a 200px column, a letterbox in a wider one;
- title `--type-h4` (17px), summary `--type-caption` (13px) clamped to 2 lines;
- tag badges hidden — they duplicate a link the whole card already carries and wrap badly at
  this width;
- no border, no radius, no background.

After: **204×473** — 202px square thumbnail, then title, read time, tag row and a 2-line summary.

**Also fixed here:** `article.showViews` was `true` with no Firebase configured, so every card and
post header rendered a permanent animated "loading" skeleton. Set to `false` — if view counts
are ever wanted, that needs a Firebase project before the flag goes back on.

#### Sidebar TOC
The theme sets no size on it, so it inherited 19px from the prose body and read as loud as the
article. It now sits on the meta scale: `--type-meta` (12px, −37%), Inter, `--ink-2` with
`--accent` for the item marking the section you're reading — the same signal as a prose link,
not a brighter black (28 Oct 2026). Navigation is chrome; the article is content.

**Hero API:** prefer `title` + `subtitle` params, which emit a real `<h1>` and `<p>`:
```
{{< hero src="featured.jpg" title="Three Passes, Three Days" subtitle="One ridge at a time." height="75" >}}
```
The legacy `overlay="**Title** <br>Subtitle"` form still renders correctly (CSS styles its
leading `<strong>` as display type) but produces no `<h1>`, so **do not use it for new pieces**.

**Centring:** `side="center"` is for standfirsts and ≤2-line passages only. Long-form body
copy is always left-aligned — centred prose has no consistent left edge for the eye to return
to. Centred blocks automatically get a 54ch measure and increased leading.

### Rules
- **Tokens are the only place raw values live.** No hex codes or px sizes in component CSS.
- Use `var(--token)` for anything a designer might want to tune. If you're writing a hex code
  in a component, you're doing it wrong.
- `!important` is banned. The file is unlayered and the theme's utilities are layered, so an
  unlayered rule already outranks every utility on the page. There are zero uses in
  `type-system.css` today; the `!mb-9` on the `lead` shortcode is Tailwind's, not ours.
- **`custom.css` is not the skin.** It loads before type-system; new work goes in type-system.
- New component = new class prefixed `ed-` (editorial).

## 9. Conventions — how to make a visual change

Written because the home hero spent months outside the system: its own inline `<style>` block,
hardcoded hex (`#0f172a`, `#f5f5f0`), inline `style=""` on cards, and no entry in §8. Nothing
here is new policy — it is §8's rules, made checkable.

### 9.1 Which file

| The change is… | Goes in |
|---|---|
| A colour, size, weight, spacing, radius, leading, tracking | a token in `type-system.css` `:root` (light mirror in `html:not(.dark)`) |
| How a component looks | the component's block in `type-system.css` |
| A shortcode's look | same, in `type-system.css` (not `custom.css` — that file is legacy) |
| Page structure / which elements exist | a `layouts/` template |
| Behaviour | `assets/js/*.js`, loaded from `extend-footer.html` |
| Anything in `themes/blowfish` | **stop** — override instead |

Load order is decided by `extend-head.html`: the theme concatenates and hardcodes its own CSS,
and ignores `params [custom] css`. Adding a stylesheet to `params.toml` does **nothing**.

### 9.2 Tokens

- **No raw values in component CSS.** Not a hex, not a px, not a `rgb()` literal. If a value
  needs to exist, it is a token; if a token needs tuning, tune it there and every surface moves.
- **Composite values are tokens too.** Shadows, gradients and full `background` stacks are
  tokens (`--hero-card-shadow`, `--hero-card-scrim`, `--hero-veil`). A gradient written inline is
  four decisions hiding in one line.
- **Channel-list tokens for alpha variants.** Store `rgb()` channels space-separated
  (`--hero-veil: 15 23 42`) so components can write `rgb(var(--hero-veil) / 0.85)`. Comma lists
  (`15, 23, 42`) **do not** accept a `/ alpha` and the whole declaration silently drops — this
  cost one debugging round on the hero veil.
- **Two ink systems, and only two.** Surface ink (`--ink-0…4`) for anything on a page surface.
  Hero ink (`--hero-ink`, `--hero-ink-dim`) for the anchor column, which sits on a photograph of
  unknown brightness. Chrome over photography (`--hero-chrome-*`) is deliberately
  mode-independent, because it is always over an image, never over a surface.
- **JS reads tokens, never duplicates them.** `hero-carousel.js` takes the rail gap from
  `getComputedStyle(...).columnGap`; it does not carry a `12`.

### 9.3 Naming

- Every site component is a `ed-` prefixed block: `.ed-card`, `.ed-hero`, `.ed-feature`.
- Elements are `__`, modifiers are `--`: `.ed-hero__rail`, `.ed-card--note`,
  `.ed-nav-btn:disabled`.
- One block per file section, headed by the lettered section comment (`/* --- E. HOME HERO --- */`).
- Sections in `type-system.css` run A tokens → B base → C prose → D editorial list → **E home
  hero** → **F article page**. A new page-level composition takes the next letter.
- `E` is subdivided (`E1` hero tokens … `E8` stacked layout) because the hero is large enough to
  need its own map; `F` is still one pass.

### 9.4 Inline styles: data may be inline, design may not

The one permitted `style` attribute is a value that comes from content — currently
`background-image: url(...)` per card, because the URL is front-matter, not design. Everything
else is a class. Rule of thumb: *if it can be written in the stylesheet without knowing which
post the visitor is reading, it belongs in the stylesheet.*

Same for markup behaviour: script lives in `assets/js/`, hooked by a `data-` attribute
(`data-hero-carousel`), so removing the block removes the behaviour with no orphan handler.

### 9.5 Page-level compositions

A full-bleed page (the hero) needs three things that are easy to get wrong:

1. **The breakout must not be clipped on `<body>`.** `width:100vw; margin-left:calc(-50vw + 50%)`
   only reaches the viewport edge while `<body>` spans it. Blowfish sets `body` to `max-w-7xl`,
   so clipping there crops the hero to 1280px and leaves bare plate down both sides.
2. **Scroll lock goes on `<html>`, scoped by `:has()`, and uses `clip` not `hidden`.**
   `html:has(.ed-hero) { overflow: clip }` — `clip` creates no scroll container, so nothing
   sticky elsewhere breaks, and `:has()` keeps it off every other page.
3. **Compensate for the fixed header with a token** (`--hero-chrome`), and give the row the same
   padding back. Nothing hardcodes 148px twice.

### 9.6 Order of work for a visual change

1. Read this file. If the change contradicts it, the change is a §-level decision — say so first.
2. Change the token or the block. Never both reinvented in one place.
3. `hugo serve`, then he looks. He is the arbiter of how it looks.
4. Verify numerically what can be verified: computed styles, rects, breakpoint sweep, build log.
5. If the change should be visually inert (**a refactor**), prove it with a pixel diff.
6. Update §8 if a file changed owner, and add a `CHANGELOG.md` line.

### 9.7 Shared primitives — use these before inventing a token

| Primitive | Use |
|---|---|
| `.ed-bleed` | Anything that must reach both viewport edges. Never re-declare `100vw` + `margin-left`. |
| `--header-offset` | Clearance under the fixed header, in either direction. |
| `--radius-pill` + `--space-control-y/x` | The one button/pill shape. |
| `--scrim-photo`, `--scrim-card` | Darkening an image so text can sit on it. |
| `--on-photo-line/-line-hi/-ink/-ink-hi/-dim` | Chrome **over a photograph** — mode-independent white, because it is never over a surface. |
| `.ed-eyebrow` (+ `--on-photo`) | The tracked uppercase label voice. One definition, everywhere. |
| `--type-*` | Every font size. A component that writes `0.6875rem` is wrong even when the number is right. |

The test before adding a `--hero-*` token: **does a second surface ever want this?** If yes it is
a global token, not a hero one. Hero-only, after this pass: the veil alphas, the landing title
size, anchor width/max, card geometry. Everything else is shared.
